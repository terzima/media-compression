# Matching source and rebuilding

Every preview release provides the project source at its tagged commit, a separate matching dependency-source archive for each native target, license notices, dependency manifests and codec build flags. Verify SHA256SUMS before extracting. Choose the dependency archive for the installer you downloaded; build flags and SDKs differ by platform.

Extract the project source and dependency archive into separate directories. The dependency archive contains all ten pinned native source archives, Rust vendor trees for the application and pngquant, the patched libpng/Little CMS bindings, exact lockfiles, build scripts, native/Rust/npm license texts and the observed codec manifest. These are source and build materials, not an additional installation requirement for ordinary users.

Use the Node/Rust/CMake/Ninja versions and platform build tools documented in the project README. Copy the native archives from `dependency-source/` into the project source's `.tools/sources/`; the build script verifies their checksums. Copy `dependency-source/patched-sys/` into `.tools/patched-sys/`. Run the README build commands from the project source directory. Source downloads remain pinned and checked. Compilation uses platform SDKs; CI evidence identifies its environment. Byte-for-byte reproduction across different SDKs is not claimed.

The supplied Rust vendor configurations can replace registry downloads: point their `directory` values at the absolute paths of the extracted `rust-vendor` and `pngquant-vendor` trees and supply those source-replacement sections through Cargo `--config` files, or merge them into the appropriate workspace's `.cargo/config.toml`. Preserve the Windows static-CRT configuration. The pngquant build uses the committed lock and the two patched binding paths; see `scripts/build-codecs.mjs`. npm dependencies remain specified by package-lock.json and can be acquired with `npm ci`; native/Rust source archives do not contain the npm registry or platform SDKs.

FFmpeg and ffprobe are standalone executables built without GPL/nonfree/network features. Their static LGPL dependencies include LAME; rebuild those executables using the supplied sources and build flags to modify or relink their libraries. pngquant/libimagequant are separately executed GPL components; their full sources, vendor dependencies and patches are supplied. The application does not prohibit modifying or reverse engineering these components. MIT licensing of project code does not replace their licenses. Native source modifications are the source replacements/locked build adjustments described in the build recipe; the original archives retain their upstream hashes.

The Windows installer also embeds Microsoft's Evergreen offline WebView2 installer. It retains Microsoft's terms and is not covered by the project MIT license or the open-source vendor archive. See [Microsoft distribution guidance](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution). Windows build evidence records its source URL, hash/version and signature-inspection outcome. Signature and clean-device qualification remain separate from this source packaging check.
